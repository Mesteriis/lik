# Local sensitive-photo screening

Selected during Task 9 and implemented as the Task 13 privacy boundary. Artifact availability alone never grants visibility: new, revised, failed and unclassified photos remain quarantined until a revision-matched manual decision or a future calibrated automatic policy permits them.

All three profiles share one `sensitive-v1` component: [Marqo/nsfw-image-detection-384](https://huggingface.co/Marqo/nsfw-image-detection-384/tree/0c26ec22111b83f106d72a55f611ec35962bcb65), Apache-2.0, ViT-Tiny with 192-dimensional hidden states. Its 22,404,720-byte source has fewer parameters than the considered Yahoo thin ResNet and substantially fewer than Falconsai/AdamCodd ViT-Base. The publisher supplies the exact architecture, ordered labels (`NSFW`, `SFW`) and timm preprocessing. The runtime artifact is the HF ONNX export bot’s immutable unmerged PR #5 commit `b2d8f0c3abe6e05062288460ecf58e42ea690e84`, independently validated against the publisher FP32 safetensors. It returns two logits; Lik must apply stable softmax in the ordered label space. The ONNX file is 22,527,617 bytes and is downloaded from HF, never bundled. Conversion provenance is explicit; export/runtime parity does not establish detection accuracy.

The selection considers publisher provenance, redistributable license declaration, model size, supported operators and documented scope. [Yahoo open_nsfw](https://github.com/yahoo/open_nsfw/tree/a4e13931465f4380742545932657eeea0a10aa48) is a credible 23,815,355-byte BSD-2-Clause alternative with narrower pornography-only scope and a legacy Caffe conversion path. [Falconsai](https://huggingface.co/Falconsai/nsfw_image_detection/tree/96cb0d0342c7afb80cab76ecc58b265fa44da256) is a 343,223,968-byte Apache-2.0 ViT-Base 224 classifier; [AdamCodd](https://huggingface.co/AdamCodd/vit-base-nsfw-detector/tree/8587de998f441aac03fdd57a85d2e4cb808c7d64) is 344,391,328 bytes at 384 pixels and documents weaker performance on generated imagery. No publisher accuracy is claimed as a Lik measurement.

The score concerns NSFW visual content. A document with financial information, an otherwise ordinary private photo, violence, or an unsupported case may need a manual sensitive override even when this classifier returns a low score. Threshold calibration is **not run**. The manifest has no release threshold. Until a reviewed calibration and disjoint test set establishes a threshold for the frozen artifact, automatic safe decisions are disabled and new photos stay unclassified. Neither a guessed 0.5 threshold nor an unmeasured mobile latency is a product guarantee.

Task 13 enforces one visibility policy at every implemented boundary: feed, timeline covers, thumbnails and caches, albums, favorites, conventional/semantic/OCR/people/duplicate search, viewer and adjacent navigation, selection, trash, share/export, AI inputs and AiGate. Newly imported or content-revised media enters quarantine before any observable thumbnail or result is published. Failed, cancelled, unavailable or stale screening retains quarantine. Room v15 stores raw classifier runs and automatic decisions against the exact model/preprocessing fingerprint, policy revision, content revision and access epoch. Manual safe/sensitive overrides are separate durable records and apply only to their recorded content revision. The legacy exposure table is only a query materialization; v14 `SAFE` rows are downgraded during migration because they lack the new provenance.

The top-bar reveal action requires `BIOMETRIC_STRONG` through the Android biometric API, with no device-credential fallback. Successful reveal exists only in memory, expires on app background, screen lock, observable user switch, relevant media-domain change and process restart, and is never restored from saved state. Unavailable biometrics, cancellation, lockout or failure keep content hidden. A monotonic reveal epoch rejects late prompt, thumbnail, viewer, OCR, export and router work. Re-lock replaces the Paging differ, clears decoded caches and protected selection immediately; protected windows use `FLAG_SECURE` while revealed.

The downloaded shared classifier runs locally in the isolated, single-heavy-task ORT process after installation of any profile. Automatic release remains disabled because no disjoint calibration evidence exists; raw logits are retained for later evaluation and the settings disclosure says review is still required. AiGate requires an authenticated reveal for hidden/sensitive media **and** its separate explicit, one-use per-photo send action; health discovery, opening the router app, or enabling the connector never authorizes image transfer.

API 37 coverage exercises default quarantine, explicit reveal queries, revision invalidation, separate manual/automatic persistence, v14→v15 migration, strong/weak/credential outcomes, stale callbacks, Activity recreation/background relock and `FLAG_SECURE`. Physical Fold biometrics, screen-lock OEM behavior, multi-window visual review, Samsung acceleration and classifier calibration remain open device acceptance work.

The [evaluation contract](../models/evaluation/DATASET_CONTRACT.md) requires independent RU/EN context slices, consented/licensed adult fixtures, calibration/test separation, false-negative and false-positive measurements, and ambiguous/out-of-scope cases. No real sensitive-photo dataset or quality score is present in Git.
