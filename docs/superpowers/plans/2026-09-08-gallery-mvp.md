# Галерея с ручным импортом — план реализации

> **Historical / superseded:** the generic Photo Picker and GridView decisions described here were replaced on 2026-09-08 by direct MediaStore viewing plus Google Photos → Share → Lik and the five-level RecyclerView timeline. The checked items below record former implementation work; they are not the current product contract. See `../specs/2026-09-08-device-media-gallery-design.md`.
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Довести Lik до удобной офлайн-галереи фотографий, которые пользователь вручную выбирает из Google Photos или отправляет через «Поделиться».

**Architecture:** Развить существующие Photo Picker/Share, `PhotoStore` и Kotlin/Views. Завершённые файлы в приватной библиотеке остаются источником истины; импорт, чтение списка, удаление и декодирование работают вне UI-потока. Полноэкранный просмотр получает отдельный экран, а Activity отвечают за отображение и пользовательские действия.

**Tech Stack:** Kotlin, native Android Views, AndroidX Activity/ViewModel/LiveData, ImageDecoder, JUnit, Android instrumentation. Существующее файловое хранилище; новые зависимости для MVP не требуются.

**Spec:** [Текущий контракт импорта](../../GOOGLE_PHOTOS_IMPORT.md), [ограничения проекта](../../../AGENTS.md) и границы MVP ниже. Запрос пользователя от 2026-09-08: галерея с ручной загрузкой из облака Google; все ML/AI-функции вне scope.

**Статус:** Реализация локального MVP завершена 2026-09-08: импорт, сетка, просмотр, выбор и удаление копий работают и проверены на API 37. Реальный импорт удалённого объекта из авторизованного аккаунта Google Photos остаётся открытым пунктом приёмки, поскольку такой аккаунт на QA-эмуляторе не настроен. Под «гугл клаудом» принят Google Photos; Google Drive и Cloud Storage вне этого этапа.

## Общие ограничения

- Kotlin и native Android Views; один `:app`, package/application ID `io.github.mesteriis.lik`.
- JDK 17, AGP 9.2.1, Gradle 9.4.1; min SDK 36, compile/target SDK 37; Android 16 на целевом Fold и Android 17 после обновления. Использовать Wrapper.
- Версии зависимостей находятся в `gradle/libs.versions.toml`; не обновлять toolchain попутно.
- EN/RU, системные светлая/тёмная темы, шрифт до 200%, изменение размера окна и Fold.
- Только выбранные фотографии. Сохранить лимиты 50 фото на операцию и 200 МиБ на файл.
- Сохранять байты, предоставленные источником, без перекодирования. Исходники в Google Photos не изменять. Источник сам может выдать обработанную версию; побайтовое совпадение с оригиналом в облаке не обещается.
- Не добавлять broad media permissions, прямую авторизацию Google, сетевой клиент, фоновые службы, автосинхронизацию или backup.
- Не добавлять ML/AI-код, модели, загрузчики, индексы embeddings, OCR, распознавание лиц, генерацию и экраны-заглушки для этих функций.
- Существующие копии сохраняются при обновлении приложения; их формат и SHA-256 ID остаются совместимыми. Копии исключены из Android backup и удаляются при удалении приложения.
- Идентичности launcher aliases, атомарное переключение и все десять PNG с alpha сохраняются.
- `references/` не изменять и не собирать. Не копировать сторонний runtime-код; при новых заимствованиях отдельно фиксировать commit, файлы и лицензию.
- В рабочем дереве уже есть незакоммиченная реализация импорта. При выполнении плана сохранять её и другие существующие изменения; не начинать с reset/clean.

## Решение по источнику и границы MVP

Рекомендуемый сценарий: **Добавить фото → системный Photo Picker → выбор фотографий → приватные копии → просмотр офлайн**. Google Photos доступен в системном окне, когда на устройстве доступен и настроен соответствующий cloud media provider. Второй вход: **Google Photos → Поделиться → Импорт в Лик**. Приложение не может гарантировать наличие Google Photos в системном окне.

Альтернативы:

1. **Photo Picker + Share — выбранный подход для плана.** Использует существующий код и выданные пользователем URI; облачную часть обслуживает источник. Проверить оба входа на целевой конфигурации.
2. **Прямой Google Photos Picker API.** Даёт отдельный Google Photos flow, но добавляет OAuth, API-сессии, polling и скачивание. Вернуться к нему отдельным решением, если существующий подход не удовлетворяет реальному сценарию.
3. **Google Drive / Cloud Storage.** Это другие источники с иными контрактами доступа. Их реализация не включена в текущую оценку работ.

MVP включает сетку, порядок от недавно добавленных к старым, полноэкранный просмотр, сведения о размере/формате/разрешении/времени добавления, множественный выбор и удаление копий из Lik с подтверждением. Время добавления подписывается именно как время добавления, а не как дата съёмки.

Альбомы, избранное, корзина, экспорт, поиск по имени/дате, теги, подробный EXIF-каталог, видео/Motion Photo и редактор остаются последующими отдельными решениями. Визуально похожие фотографии не объединяются; существующая точная SHA-256-дедупликация входит в обычный импорт и не требует ML.

## Этап 5. Удаление локальных копий

**Файлы:** `imports/PhotoStore.kt`, `imports/ImportViewModel.kt`, `ui/MainActivity.kt`, `ui/PhotoAdapter.kt`, `gallery/PhotoViewerActivity.kt`, обе `strings.xml`; `PhotoStoreTest.kt`, `GalleryTest.kt`, `PhotoViewerTest.kt`.

**Контракт:** `PhotoStore.deletePhoto(id: String): Boolean` принимает только 64 строчных hex-символа; удаляет соответствующий `<id>.image` внутри приватной папки. Возвращает `true` при удалении, `false`, если файла уже нет; неверный ID отклоняется, ошибка удаления передаётся как `IOException`. Не принимает произвольный File/путь.

```kotlin
@Test fun deletingCopyPreservesInputAndAllowsReimport() {
    val source = temporary.newFile("source.jpg").apply {
        writeBytes(byteArrayOf(1, 3, 5, 7))
    }
    val library = store()
    val saved = library.importPhoto(source.inputStream()).photo
    assertTrue(library.deletePhoto(saved.id))
    assertTrue(source.exists())
    assertTrue(library.photos().isEmpty())
    assertTrue(library.importPhoto(source.inputStream()).added)
}
```

## Проверенные официальные источники

Проверено 2026-09-08:

- [Android Photo Picker](https://developer.android.com/training/data-storage/shared/photo-picker): доступ только к выбранным файлам, выбор из доступного cloud provider, ограничения выбора и срок URI grants.
- [Cloud media provider](https://developer.android.com/guide/topics/providers/cloud-media-provider): устройство облачной интеграции с системным picker; Lik использует её как потребитель выбранных URI.
- [Google Photos Picker API](https://developers.google.com/photos/picker/guides/get-started-picker): отдельный OAuth/API flow, оставленный за рамками выбранного подхода.
- [ImageDecoder](https://developer.android.com/reference/android/graphics/ImageDecoder): декодирование локальных файлов с заданным размером результата.
